Architecture decisions

  • Sources are one table plus a morph pivot with short type names (destination, route, contribution), so renaming a class cannot break stored rows. Orphaned sources are deleted when a record's list changes, and every change is audited.
  • Geography without PostGIS (D3 pending): a bounding-box filter in SQL, then exact straight-line distance in PHP (App\Support\Geo, unit-tested). It is marked as a shortcut to replace with PostGIS ST_Distance once D3 is approved.
  • Saved items are one table with a type column (not a morph relation), checked against published content on write and filtered again on read, so items that are later unpublished drop out.
  • The author's addendum is a separate field shown under the report, never a change to the body. It is public only after review, so riders cannot bypass moderation.

Failures and resolutions

  • The experience page and the moderation queue showed their loading state on every refresh. That unmounted the content, so confirmation messages and an open history panel disappeared. Both now keep their content during a refresh (found by the new E2E tests).
  • The moderation card read its item once and then ignored updates; it now follows the prop via toRef.
  • The route-authorization matrix test refused the new routes until they were classified (journeys public, users/me/saved account-level). This is the intended safety net.
  • A Playwright label locator also matched the swap button; fixed with exact matching.
  • One chained check command was killed (exit 137, low memory with the owner's servers running); the checks were rerun one at a time.
  • Another session had written "session 11" entries to the handoff in parallel. This session's entries were relabelled session 12; the other session's text was left as it was.

Security implications

  • Every new endpoint has a policy or permission, validation and a feature test, including refusal cases (guests 401; other riders 403; riders on staff routes 401; wrong report parent 404). Staff decisions write audit rows.
  • No self-review: corrections, confirmations and reports go through ContributionPolicy (the author cannot confirm or report their own item); moderation keeps the existing no-self-review rule.
  • Correction requests and moderation notes are visible only to the author and moderators. Moderator names appear only in the staff history, never to riders.
  • Saved rows are owner-only and never exposed publicly; drafts and archived items cannot be saved. Source links are validated as http(s) in Laravel and with a database check.
  • The public journeys endpoint returns only published rows, validates slugs and radius (1 to 50 km), and caps result sizes.
