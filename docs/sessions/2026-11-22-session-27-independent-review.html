Replacing the raw account id with a keyed HMAC

  • Feasible:
    • store HMAC-SHA256(dedicated key, user_id) when a request finishes, and keep the raw id only while it is scheduled;
    • after a backup restore, compute the HMAC of each restored user id and match it against records less than a year old.
  • Safe implementation needs:
    • a key separate from APP_KEY (rotating that would break matching), kept outside the database and its backups;
    • old keys kept, because re-keying is impossible once the raw ids are gone;
    • a migration that adds the column, backfills finished rows, makes user_id nullable and clears it;
    • a tested restore runbook.
  • Value is limited today:
    • audit_logs.actor_id keeps the same raw id indefinitely;
    • D-10 keeps choices as categories only, so re-applying a deletion after a restore cannot reproduce the rider's choices. The code would delete every public contribution, including ones kept anonymously: privacy-safe, but content is lost;
    • no restore tool or runbook exists yet.
  • Not changed. This needs an owner decision.
