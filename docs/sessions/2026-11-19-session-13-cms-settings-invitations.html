Work completed

  • CMS modules. Pages with content blocks, FAQs, blog posts with categories, tags and authors, team members, popups and banners. They share one table and one config file (config/cms.php), which also drives the staff forms. Each supports drafts, a separate publish permission, schedule and expiry, ordering, SEO fields, slugs, signed preview, search, filters, pagination and an audit trail. Public pages: /pages/:slug, /faq, /blog, /blog/:slug, /team, /contact, plus banners and an accessible popup.
  • Contact messages. A public form with a honeypot field and a rate limit, and a staff inbox with read and unread, status, search and delete. Sender emails are visible only with contact.view.
  • Settings. Four new groups:
    • Mail: SMTP override with an encrypted password, connection test, and a test email that goes only to the signed-in staff member.
    • Maps: tile URL, attribution and default view, plus geocoding and routing provider fields with a test that refuses private hosts. Nothing is reported as connected.
    • Security: staff session limits and sign-in attempts.
    • Trust: the corroboration threshold and window.
  • Trip invitations with consent. Adding a member now sends an invitation. The rider accepts or declines within 14 days, and the owner can cancel it. Before accepting, the rider sees only the title, the inviter and the role.
  • Journey page add-to-trip. Services and destinations can be added to a trip directly; the same service twice on one trip is refused by the API.
  • Community corroboration. A published report is marked "corroborated by other riders" once enough distinct eligible riders confirm it within the window (default 3 riders in 90 days). This is never official verification.
  • Contribution-only suspension. Staff can pause a rider's contribution rights with a reason and an end date. The rider can appeal once, and staff lift or uphold the pause. Everything is audited and the rider is notified. Account suspension is unchanged.
  • Events. Organizers can remove approved riders before the start, and the waitlist moves up. Postponing can set new dates.
  • Defects found and fixed:
    • media_usages was never written, so images in use could be deleted. It is now written for CMS entries, homepage sections and settings images.
    • Layout shift was 0.39 on the homepage and 0.23 on Explore; it is now 0.
    • Staff dialogs shared one title id, which confused aria-labelledby.

Architecture decisions

  • One generic CMS table rather than nine modules. Each type's fields are declared once, and both the validation rules and the staff form come from that declaration. Text is plain text (no HTML), so there is no rich-text sanitizer to maintain.
  • CMS staff routes are registered once per type, each behind that type's own permission (enforced by the route-matrix test). Publishing is a separate permission.
  • Staff mail settings are applied the first time the mail manager is used in a request or job. Saving them restarts queue workers.
  • Corroboration counts "still accurate" confirmations from distinct eligible riders, as you directed. Matching independent reports on the same stretch is recorded as a future refinement.

Failures and resolutions

All are listed in docs/handoff.md §5 (session 13). The main ones:

  • Route defaults reached the controllers in an unexpected order; the controllers now read the type and answer from the route.
  • The route matrix refused unclassified routes and a constrained route that answered 404 before authentication.
  • PDO treats ? as a placeholder, so the JSON tag query uses jsonb_exists().
  • The contact-form rate limit blocked repeated E2E runs; the E2E API now raises it with CONTACT_PER_HOUR.
  • The browser caches the popup list for 60 seconds, so the test creates the popup before the first page visit.

Security implications

  • Every new endpoint has a permission or policy, validation and tests, including refused cases: riders on staff routes, a staff member without the module permission, an editor without the publish permission, someone else's invitation (404), and a staff member pausing their own linked rider account.
  • Secrets (mail password, provider keys) are stored encrypted and returned only as "set or not set". They never appear in audit rows or in /site.
  • The provider test calls only https URLs and refuses private, loopback and reserved addresses, so it cannot be used for server-side request forgery. The test email can go only to the signed-in staff member, so it cannot act as an open relay.
  • Contact messages store an HMAC of the sender's network address, not the address itself. Sender emails are visible only with contact.view.
  • Private trips: membership now requires consent, and before accepting the invitee sees only the title, inviter and role.
  • Map attribution is escaped before Leaflet renders it as HTML.

Database changes

Two additive migrations were applied with the owner role to myridenepal and myridenepal_e2e: cms_entries and contact_messages, then trip_invitations and contribution_suspensions. The permission registry was synced (49 keys). Nothing was dropped or reset, and existing trip members remain members. Rollback: each down() drops only its own tables.

  • No geocoding or routing proxy, so no detours or riding times: this needs a provider (D2).
  • Durable file storage (D1) and crawler-visible SEO (D4) are not done.
  • Branding beyond the share image (logos, favicon, colours) and notification/feature settings are not built.
  • About, Privacy and Terms pages need texts written by you.
  • WebKit, axe, Lighthouse and a screen-reader check have not been run.
