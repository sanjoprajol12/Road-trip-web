Findings

  1. Why both apps stop: admin pnpm dev is run-p dev:public dev:admin: one parent process for both Vite servers. There is no runtime coupling. The two apps share one package.json, Vite config, lockfile, .env, CI, E2E and repo, so they cannot be deployed with separate configurations.
  2. Vercel: no linked project or logs here; Vercel can run the API container (Dockerfile.vercel is the documented mechanism). GitHub HEAD is still the pre-Option-B layout. It cannot serve pages without a production database (sessions and cache are database-backed, DB defaults to 127.0.0.1) and APP_KEY; frontends have no vercel.json (no API rewrite, no SPA fallback); local-disk uploads and the database queue are not durable on Vercel; Hobby terms are an owner question.
  3. Authentication: one guard, one users table, one cookie and 7-day session for riders and staff; the staff app signs in through the rider endpoint; staff reset links go to the public site; any rider can be given a staff role. No escalation exists (every staff route is permission-checked and tested; registration accepts three fields), but rider credentials can open a staff-origin session and become staff credentials.
  4. Frontend organisation: 37 .vue files call the API directly; only three service files; PeoplePage, SettingsPage, MediaPage, TripPage mix several jobs (files are under 300 lines: responsibility, not size, is the problem); 10 API types defined in both apps; all runtime dependencies used.
  5. Homepage: hero copy, headline lines, CTAs, hero image and credit, section headings and texts, freshness legend, header menu and footer copy are hard-coded; no CMS tables exist beyond the media library and settings.
  6. Requirements: 261 rows (225 audited + 36 new): 87 complete and tested, 19 under-tested, 66 partial, 15 documented-not-built, 67 missing, 6 unverifiable, 1 suggestion. The original master brief was never saved as a file.

Recommendations (proposed, not implemented)

  • Option A: Laravel stays at the web root; public app in web/frontend/; staff app at the admin root. Commands: composer dev (API :8010), pnpm dev in web/frontend (:5180), pnpm dev in admin (:5181). Three Vercel projects, each with its own config.
  • Staff accounts separated: own table, guard, cookie, shorter sessions, login, password broker, invitation-only provisioning, optional 2FA with Fortify's built-in support (no new package), and ten tests including "a rider cannot authenticate as staff".
  • Modules: one page per responsibility, a service and types per feature, shared admin UI primitives, settings as one page per group with tabs.
  • Homepage: section registry with draft/published data, featured items, preview, publish, seeded with the current copy so nothing changes visually on day one.
