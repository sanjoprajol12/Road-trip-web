Conflicts found and how they are handled:

  • Fixed staff roles (user_roles + can:staff/can:admin) vs module/action permissions: plain tables (no new package), system roles seeded to today's rights, backfill, gates switched, old table retired only after verification. Permissions are defined in code, because a UI-created permission nothing checks would grant nothing.
  • SMTP and storage settings from the database vs Laravel's boot-time config: applied per request from cache, .env as fallback; secrets encrypted with the app key, never returned, masked in audit rows.
  • Maintenance mode: artisan down is per-instance and ephemeral on Vercel: use a database flag.
  • SEO and social metadata vs a client-rendered SPA: crawlers do not see Vue-set tags (decision D4).
  • Configurable tile URL vs a static Content Security Policy: tile hosts from an allow-list.
  • Routing and geocoding are separate providers from tiles; their keys stay in Laravel behind proxy endpoints; no time or distance is shown without a provider or an "estimate" label.
  • Places vs services: services stay in service_points, points of interest get a new places table; rider-submitted places use the moderation rules.
  • Route discovery needs real geometry (today only segment endpoints) and spatial queries: PostGIS is available locally (3.3.7) but needs approval (D3).
  • Durable media on Vercel needs an object store and a new Composer package (D1).
