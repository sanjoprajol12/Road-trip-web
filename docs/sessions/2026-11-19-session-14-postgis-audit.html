Session 14: PostGIS pre-activation safety audit

2026-11-19 · Claude Code (Opus 5.5) · Inspection only · Nothing committed · No database, extension, migration, Docker or configuration change

Objective

Check whether PostGIS can be enabled safely, and plan backups, schema, migrations, rollback and tests, without enabling anything. The full plan is docs/database/POSTGIS_ACTIVATION_PLAN.md.

Findings

  • PostgreSQL 17.12 runs in the Supabase image public.ecr.aws/supabase/postgres:17.12.0.000, with the data volume supabase_db_my-ride-nepal.
  • PostGIS 3.3.7 (with raster, sfcgal, topology and tiger) and pgrouting 3.4.1 are available but installed in no database.
  • PostGIS is not a trusted extension, but Supabase's supautils lists it as privileged. The postgres role (not a superuser, but a member of supabase_privileged_role) can create it; mrn_owner and mrn_app cannot.
  • Laravel pins search_path to public, while the server default also includes extensions.
  • CI uses postgres:17, which has no PostGIS.
  • There are no geographic types yet. Coordinates are numeric(9,6) on destinations, service points and route segments.
  • Dev data: 4 destinations without coordinates, and no service points, routes or segments.
  • Laravel 12 supports geography columns. The test suite's migrate:fresh leaves PostGIS objects alone as long as --drop-views is never used.
  • Client tool versions differ: pg_dump 18.6 on the host, 17.12 in the container. The plan uses the container's.

Proposal (not applied)

  • Install PostGIS in an extensions schema of each project database, from the setup script as postgres, and add extensions to Laravel's search_path.
  • Generated geography(Point,4326) columns built from the existing latitude and longitude (kept as the source of truth), route_segments.path as geography(LineString,4326), a new moderated places table, and GiST indexes.
  • A GEO_ENGINE feature flag (default php), parity tests between both engines, and a rollback that never drops the extension.
  • Exact backup, verification, isolated-restore and row-count comparison commands (plan section 3).

Commands executed

Read-only only: docker ps, docker inspect (mounts), psql -c "select ..." and show against the three project databases and postgres, tool --version checks, and reading files under vendor/laravel, config, database/migrations, scripts and .github.

Tests

None were run. This session changed no code.

Security implications

Activation needs the privileged postgres role once per database. The application role mrn_app still gets no DDL rights, and geography columns must stay out of API output ($hidden).
