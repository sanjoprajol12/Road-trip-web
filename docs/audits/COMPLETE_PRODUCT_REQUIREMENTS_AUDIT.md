# Part 3: Architecture decision (final: Option B)

**Decided by the owner on 2026-11-18; authoritative; overrides older handoffs and session reports.**
- `web/` = Laravel 12 backend only (REST API `/api/v1`, Fortify, Sanctum, migrations, models, policies, actions, services, CMS and settings backend, auth, notifications, audit). No Vue app, Vite frontend or frontend build output.
- `admin/` = both Vue 3 + TypeScript + Vite applications: `src/apps/public/` (public website and rider platform) and `src/apps/admin/` (staff dashboard and CMS), with separate route trees, layouts, navigation, guards and feature folders; they may share UI components, API client, types, utilities and design tokens (`src/shared/`) inside the admin repo. No third repository or shared package.

**Status: implemented and verified in session 7.** Recovery point: git `HEAD` of both repos (`web` ccc0f45, `admin` 1e9563e, both pushed) plus an archive of both working trees in `/var/www/html/Road-trip/_backups/2026-11-18-pre-option-b/` (includes git-ignored `.env` files; owner-only permissions). Evidence: Laravel 55/55; both apps type-check, lint, 14 unit tests, both builds; E2E 43/43 (public 27, staff 16) before and after removing the old public app from `web`; `GET /` on Laravel now 404, `/api/v1/health` 200.

**Conflicts with the previous structure (each resolved in the migration):**
1. Laravel served the public SPA (`routes/web.php` fallback, `public/app`, SPA CSP branch in `SecurityHeaders`, Node stage in `Dockerfile.vercel`). Under Option B the public SPA is a static build served from its own host that proxies `/api` and `/sanctum` to Laravel (same-site cookies), exactly like the staff app.
2. Email links use `APP_URL` as the root: `APP_URL` must be the **public website origin** (unchanged rule, now documented).
3. `SANCTUM_STATEFUL_DOMAINS` must include the public preview origin (:4180) used by E2E.
4. CLAUDE.md "No shared code between the repos" stays true (nothing crosses repos); code shared between the two apps lives inside `admin/src/shared`.
5. Web E2E moves to `admin/e2e/public`; CI for frontends moves to the admin repo; the web CI keeps backend tests only.
6. Session 5's Vercel container builds the SPA inside the Laravel image; under Option B the Laravel image builds no frontend, and the two SPAs are deployed separately (deployment choice for the owner).
