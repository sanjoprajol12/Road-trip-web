# API Documentation

- Generated reference (Scribe, from routes and validation rules): `web/public/docs/index.html`, served at `/docs` by Laravel. OpenAPI: `public/docs/openapi.yaml`; Postman: `public/docs/collection.json`. Regenerate with `php artisan scribe:generate` (no live requests are made).
- Base path `/api/v1`. JSON in, JSON out. Errors `{message, errors?}`.
- Auth: Sanctum SPA cookies. Call `GET /sanctum/csrf-cookie`, then send `X-XSRF-TOKEN` on POST/PUT/PATCH/DELETE (axios does this automatically).
- Status codes: 401 not signed in · 403 not allowed (also unconfirmed email, suspended account) · 404 not found or not visible · 422 validation (field errors) · 423 password confirmation needed · 429 rate limited.
- Pagination: Laravel paginator (`data`, `links`, `meta` or `current_page`/`last_page`/`total`).

## Endpoint groups (see `php artisan route:list --path=api`)
| Group | Endpoints |

| CMS (public) | `GET content/{type}` (faq, post, blog_category, blog_tag, author, team_member, popup, banner; posts take `q`, `category`, `tag`, `author`, `page`; banners take `placement`), `GET content/{type}/{slug}` (page, post, author; drafts with `X-Preview-Token`), `POST contact` (honeypot `website`, 5/hour per address by default, `CONTACT_PER_HOUR`) |
| CMS (staff) | `GET admin/cms/types` (descriptors from config/cms.php, limited to the caller's permissions), `GET/POST admin/cms/entries/{type}`, `PUT/DELETE admin/cms/entries/{type}/{id}` (module permission per type; publishing needs `cms.content.publish`; published items must be archived before deletion); `GET admin/contact-messages`, `PATCH/DELETE admin/contact-messages/{id}` (`contact.view` / `contact.manage`) |
| Trip invitations | `POST trips/{id}/members` now creates an invitation (14 days); `GET users/me/trip-invitations`; `POST trip-invitations/{id}/accept`, `POST trip-invitations/{id}/decline`; `DELETE trips/{id}/invitations/{id}` (owner) |
| Contribution pauses | staff: `POST admin/users/{id}/contribution-suspension` (until, reason), `POST admin/users/{id}/contribution-suspension/review` (decision lifted/upheld, note); rider: `POST users/me/contribution-appeal`; `GET users/me` returns `contribution_suspension` |
| Settings (new groups) | `mail`, `maps`, `security`, `trust` under `GET/PUT admin/settings/{group}`; `POST admin/settings/mail/test-connection`, `POST admin/settings/mail/test-email`, `POST admin/settings/maps/test` (`which`: geocoding, routing) |
| Places of interest | public: `GET places?q&category&destination&page`, `GET places/{slug}` (published; the submitter and staff previews also see their own unpublished one; returns `nearby` places within 10 km and destinations within 30 km, straight-line, and up to 5 experiences); rider (confirmed, not suspended, contribution rights): `POST places` (always `pending_review`, duplicate check 422 with `duplicate`), `PATCH places/{id}` (own, while pending or changes requested), `POST places/{id}/corrections`, `GET users/me/places`; staff: `GET/POST admin/places`, `PUT admin/places/{id}`, `GET admin/places/{id}/history` (`places.manage`), `POST admin/places/{id}/decision` (publish, unpublish, request_changes, reject, archive; `places.publish`), `GET admin/place-corrections`, `POST admin/place-corrections/{id}/decision` (`places.publish`). Places also appear in `GET destinations/{slug}` (`nearby.places`), `GET journeys` (type `place`), saved items (type `place`) and contributions (`place_id`). |
| Trips and places (session 17) | `POST trips/{id}/stops` accepts `place_id` (published only; once per trip, 422 otherwise; editors and owners only); trip responses return each stop with `place`, `destination`, `service` (published only; `linked_unavailable` when it was withdrawn) |
| Routes in trips (session 19) | `POST trips/{id}/route-parts` with `route_id` (published only) and either `whole: true` or `segment_ids[]` and/or `checkpoints[]` (`{segment_id, at: start|end}`), optional `reversed`, `day`: appends stops in riding order; 422 names anything already on the trip, refuses stretches of another route, and refuses a whole route together with its stretches. `PUT trips/{id}/stops/order` with `ids[]` (every stop of the trip, exactly once; 422 if stale). Both editors and owners only. Stops now carry `route_part`, `route_segment_id`, `route` (recorded totals and counts of stretches without distance, time or track), `stretch`, `checkpoint`; route stops keep their route links on `PATCH` |
| Trip budgets and planning (session 20) | expenses take `status` (`planned` default, `spent`); `amount_npr` is optional while planned and required when spent (422 "Enter the amount you spent.", also when a PATCH would leave a spent row without one). Trip responses add `budget` (`planned_npr`, `spent_npr`, `planned_without_amount`; entered amounts only, NPR) and per stop `tracks` (recorded tracks of a route or stretch stop; empty when none). `linked_unavailable` now also covers a withdrawn destination. `expense_total_npr` stays (sum of entered amounts) for compatibility |
| Upload policy (session 24) | `POST contributions/{id}/media` and `POST admin/media` answer **422** on the file field with the staff message when uploads are paused or storage is not durable (or "The image could not be stored right now. Try again later." when a write fails); authorization and validation errors come first as before. `GET site` adds `uploads: {enabled, message}`; `GET health` adds `uploads: enabled|paused`; staff `GET admin/settings/storage/upload-status` (`settings.storage.manage`) returns `{allowed, reason, disk, driver, environment}`. Settings group `storage` adds `uploads_enabled`, `uploads_paused_message` |
| Account deletion and export (session 25) | Rider (signed in; works while suspended and during the cooling-off):<br>• `GET/POST/DELETE users/me/deletion`: summary; request with `password`, `confirm` and `choices` per public contribution (422 when any is missing); the explicit cancel.<br>• `POST users/me/export`: password; ZIP in the response, nothing stored.<br>• `POST/DELETE users/me/deletion/offers`, `GET users/me/ownership-offers`, `POST ownership-offers/{id}/accept\|decline`.<br>During the cooling-off, rider write routes answer **403** with the deletion date. `users/me` adds `deletion_scheduled_for`. Anonymised contributions and organizer-less cancelled events show `author`/`organizer` as `{id: null, display_name: "Former rider", ...}`.<br>Staff: `GET admin/account-deletions` (`users.deletions.view`); `GET admin/moderation-evidence[/{id}[/files/{n}]]` and `POST admin/moderation-evidence/{id}/release` (`moderation.evidence.view`, views audited).
